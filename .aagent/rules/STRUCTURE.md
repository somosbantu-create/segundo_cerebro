# Guia de Estilo de Pensamento (STRUCTURE.md)

Este documento define a **alma** e a **estrutura** de entrega de qualquer conhecimento gerado ou manipulado pelos agentes do framework Constellation.

**TODOS OS AGENTES DEVEM CONSULTAR ESTE ARQUIVO ANTES DE SALVAR OU MODIFICAR CONTEÚDO NO OBSIDIAN, NOTION OU DRIVE.**

### 1. Filosofia de Estruturação
- **Atomização primeiro:** Nunca crie blocos de texto monolíticos. Fatie temas complexos utilizando a técnica **Zettelkasten**. Uma nota, um conceito.
- **Conectividade:** Nenhuma nota deve existir isolada (órfã). Sempre inclua `[[links_bidirecionais]]` para Mapas de Conteúdo (MOCs) ou notas relacionadas.
- **Densidade com Clareza:** Mantenha a profundidade técnica, mas use linguagem acessível. O eu do futuro precisa ler rapidamente.

### 2. Regras de Template (Zettelkasten + Reflexão)
Sempre que uma nova nota for finalizada, ela **deverá obrigatoriamente** terminar com o seguinte bloco:

```markdown
---
### 💭 Reflexão para o Eu do Futuro (Feedback Loop)
1. Como esse conceito se aplica aos nossos projetos?
2. Qual o limite técnico ou ético dessa ideia no mercado audiovisual?
3. O que falta pesquisar para que isso se torne uma aplicação prática?
```

### 3. Integrações Externas
- **No Notion:** Use marcadores limpos, adicione resumos de 1 parágrafo das notas do Obsidian.
- **No Google Drive:** Nomenclatura de arquivos deve sempre conter a data invertida (ex: `20260417_Arquivo.pdf`).

*(Este documento é orgânico e deve ser atualizado através do processo de Feedback Loop no CORE.md).*
